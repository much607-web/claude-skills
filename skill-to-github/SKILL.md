# 스킬 → 깃허브 업로드

사용자는 비개발자일 수 있다. 기술 용어(저장소, 커밋, 푸시 등)는 처음 나올 때 한 줄로 쉽게 풀어서 설명한다.

## 1. 올릴 스킬 고르기
선택지 질문 도구(AskUserQuestion)로 묻는다. 도구가 없으면 텍스트로 묻는다.
- 어떤 스킬을 올릴지 (사용자가 가진 스킬 목록에서 복수 선택)
- 공개 범위는 여기서 묻지 않는다. 2~3단계 점검 후 추천과 함께 묻는다.

## 2. 민감정보 점검 (모든 파일)
스킬 폴더 안의 **모든 파일**을 끝까지 읽는다 (SKILL.md뿐 아니라 참고 문서, 스크립트, 예시 파일, 템플릿 포함). 읽을 수 없는 파일(이미지, 엑셀 등)은 열어서 내용을 확인하고, 확인이 불가능하면 목록에 "직접 확인 필요"로 표시한다.

찾을 항목:
- 실명, 이메일, 전화번호, 주소, 계정 아이디
- 회사명, 거래처·프로젝트명, 금액, 내부 수치
- 비밀번호, API 키, 토큰 같은 접속 정보 (발견 시 무조건 삭제 추천)
- 특정 개인 PC 경로 (예: `C:\Users\홍길동\...`)
- 개인 업무 습관처럼 남에게 의미 없는 내용

결과는 표(파일 / 위치 / 내용 / 추천: 삭제·일반화·유지)로 보여주고 확인받는다. 원본 스킬은 고치지 않고 업로드용 사본에만 반영한다.

## 3. 스킬별 공개 여부 추천
점검 결과를 바탕으로 스킬마다 아래 셋 중 하나를 추천하고, 이유를 한 줄로 붙인다.

| 추천 | 기준 |
|---|---|
| **공개 가능** | 일반화 후 민감정보가 남지 않고, 다른 사람도 그대로 쓸 수 있는 범용 스킬 |
| **공개용 버전 따로 만들기** | 쓸모는 범용적이지만 개인 맞춤 내용(이름, 회사 규칙, 문체 등)이 핵심 곳곳에 섞여 있음. 원본은 비공개, 일반화한 사본을 공개 |
| **비공개 추천** | 개인 문체·업무 규칙 자체가 스킬의 핵심이거나, 지워도 회사·거래 맥락이 추측될 수 있음 |

판단이 애매하면 더 안전한 쪽(비공개)을 추천한다. 추천표를 보여준 뒤 선택지 질문으로 최종 공개 범위를 받는다:
- "추천대로 진행 (추천)" / "전부 비공개 저장소로" / "직접 고르기"
- 공개와 비공개 스킬이 섞이면 저장소를 두 개(공개용·비공개용)로 나누자고 제안한다.

## 4. 업로드 폴더 만들기
```
<저장소이름>/
├─ README.md
├─ LICENSE            (공개 저장소일 때)
└─ <스킬이름>/...      (스킬마다)
```
- README.md: 한 줄 소개, 스킬 목록 표(이름 / 하는 일 / 사용 예시 문장), 설치 방법 (claude.ai: 스킬 폴더를 zip으로 압축해 설정 → 기능 → 스킬에서 업로드 / Claude Code: 폴더를 `~/.claude/skills/`에 복사). 한국어 기본, 공개 저장소면 영어 요약 추가.
- LICENSE: 특별한 요청이 없으면 MIT. 저작권자 이름은 사용자에게 묻는다 (닉네임·깃허브 아이디도 가능).
- 폴더 전체를 zip으로 묶어 전달한다.

## 5. 최종 확인 (공개 저장소면 필수)
올리기 직전에 아래를 한 번 더 보여주고 "이대로 공개해도 될까요?"를 확인받는다.
- 올라갈 파일 목록
- 2단계에서 "유지"로 남긴 항목과 "직접 확인 필요" 항목
- 주의: 깃허브는 수정 이력이 남아서, 한 번 공개한 내용은 나중에 지워도 예전 기록에서 볼 수 있음

## 6. 업로드
**A. 깃허브가 연결돼 있고 저장소가 있을 때 (자동)**
1. 저장소 접근 도구로 저장소를 세션에 추가 (쓰기 권한)
2. 저장소를 내려받아 파일을 넣고, 변경 내용을 한 줄로 설명한 기록(커밋)을 남긴 뒤 깃허브로 올린다(푸시)
3. 완료 후 저장소 링크를 알려준다

**B. 연결이 안 돼 있거나 저장소가 없을 때 (직접 업로드 안내)**
1. zip 전달 → 압축 풀기
2. github.com 로그인 → 우측 상단 + → New repository → 이름 입력, Public/Private 선택, README 추가 체크 해제 → Create
3. "uploading an existing file" 클릭 → 압축 푼 폴더 *안의* 파일·폴더를 전부 끌어다 놓기 → Commit changes
4. 저장소 주소를 알려주면 다음부터 A 방법도 가능하다고 한 줄 안내

## 7. 마무리
- 저장소 링크, 올라간 스킬 목록만 짧게 보고
- 공개 저장소면 "다른 사람은 README의 설치 방법대로 쓸 수 있다" 한 줄

## 업데이트 요청 시
바뀐 스킬만 2~3단계를 다시 하고(공개 여부가 바뀌었으면 알림), README 표를 갱신해서 같은 저장소에 올린다. 기존 파일을 지우는 경우에는 반드시 먼저 묻는다.
