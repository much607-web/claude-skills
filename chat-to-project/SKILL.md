# 채팅 → 프로젝트 전환

Claude는 프로젝트를 직접 만들거나 채팅을 옮길 수 없다. 대신 사용자가 새 프로젝트에 붙여넣기만 하면 되는 '전환 꾸러미'를 만든다. 프로젝트의 핵심 가치는 영역 분리이므로, 꾸러미를 만들기 전에 반드시 영역을 먼저 정한다.

## 1. 대화 훑기
현재 대화 전체에서 실제로 나온 내용만 뽑는다 (추측 금지).
- 다룬 주제·작업 덩어리들
- 각 덩어리의 목적, 확정된 결정, 핵심 사실·숫자, 남은 일, 사용한 파일·링크
- 사용자가 요청한 형식·톤·금지사항

## 2. 영역 분리안 제시 → 사용자에게 묻기 (필수 단계)
뽑은 덩어리를 묶어 프로젝트 분리안을 만들고, 선택지 질문 도구(AskUserQuestion)로 고르게 한다. 도구가 없으면 텍스트로 묻는다.

분리 기준 (위에서부터 우선):
1. 결과물이 다르면 분리 (예: 보고서 vs 엑셀 모델)
2. 공유 대상·기밀 수준이 다르면 분리 (업무 vs 개인)
3. 지침(형식·톤)이 서로 충돌하면 분리
4. 같은 자료를 계속 같이 참조하면 합치기

질문 구성:
- Q1. 분리 방식: 추천안을 첫 번째에 '(추천)'으로. 보통 "하나로 통합 / 추천 분리안(N개) / 더 잘게 분리"
  - 각 선택지 설명에 프로젝트 이름과 담길 주제를 한 줄로
- Q2. (분리 선택 시 필요하면) 애매한 주제를 어느 프로젝트로 보낼지
- 사용자가 같은 성격의 기존 프로젝트를 언급했다면 "기존 프로젝트에 추가" 선택지도 넣는다

사용자가 자리에 없으면 추천안으로 진행하고 맨 위에 "추천 분리안(○개)으로 진행함" 한 줄 표기.

## 3. 민감정보 점검
- 회사명, 거래처, 금액, 개인정보 등 민감해 보이는 항목은 넣기 전에 "그대로 둘까요, 가명으로 바꿀까요?"를 한 번만 묻는다 (2단계 질문과 함께 묻는 것이 좋음).
- 업무 영역과 개인 영역 내용이 한 파일에 섞이지 않게 한다.

## 4. 영역별 꾸러미 만들기 (프로젝트마다 파일 3개)
파일 이름 앞에 프로젝트 이름을 붙인다 (예: `보고서_지침.md`).

**① [이름]_지침.md** — 프로젝트 '지침(Instructions)' 칸에 붙여넣을 내용. 300단어 이내.
- 이 프로젝트의 목적 1~2줄, 다루는 범위와 다루지 않는 범위
- Claude의 역할, 답변 형식·톤, 항상 지킬 원칙
- "작업현황.md를 먼저 참고할 것"

**② [이름]_작업현황.md** — 프로젝트 '지식(Knowledge)'에 올릴 파일.
- 작성일 / 배경 / 결정사항(표) / 핵심 사실·숫자 / 남은 일(체크박스) / 열린 질문 / 참고 파일 목록
- 다른 프로젝트로 간 주제는 넣지 않고, 연관이 있으면 "관련: ○○ 프로젝트" 한 줄만

**③ [이름]_첫메시지.txt** — 새 채팅에 처음 보낼 1~3줄.
- 예: "작업현황.md 기준으로 이어서 하자. 남은 일 중 1번부터."

파일을 만들어 사용자에게 전달한다. 사용자가 저장 폴더를 지정했다면 그곳에도 저장한다.

## 5. 안내 (짧게)
프로젝트별로 아래 순서만 안내.
1. 사이드바 프로젝트 → 새 프로젝트 (이름 제시)
2. 지침 칸에 ① 붙여넣기
3. 지식에 ② 업로드 + 해당 영역 원본 파일 업로드
4. 새 채팅에서 ③ 보내기

## 업데이트 요청 시
"작업현황 업데이트해줘"라고 하면 기존 작업현황.md를 바탕으로 이번 대화의 새 결정·진행만 반영한 새 버전을 만든다 (원본을 덮어쓰지 않고 날짜를 붙인 새 파일). 이번 대화에 다른 영역 내용이 섞여 있으면 어느 프로젝트로 보낼지 먼저 묻는다.
